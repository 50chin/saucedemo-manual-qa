# Test Plan — SauceDemo

## 1. Общая информация

* **Project:** SauceDemo Manual QA
* **Application:** SauceDemo — демонстрационный интернет-магазин
* **Application URL:** [https://www.saucedemo.com/](https://www.saucedemo.com/)
* **Document type:** Test Plan
* **Version:** 1.0
* **Testing type:** Manual Testing
* **Status:** Initial draft

## 2. Цель тестирования

Проверить основные пользовательские сценарии интернет-магазина SauceDemo, выявить возможные дефекты и оценить соответствие фактического поведения приложения ожидаемому

Основные цели:

* Проверить авторизацию пользователей
* Проверить отображение каталога и сортировку товаров
* Проверить добавление и удаление товаров из корзины
* Проверить процесс оформления заказа
* Проверить навигацию между страницами
* Зафиксировать результаты тестирования и возможные дефекты

## 3. Объект тестирования

В рамках проекта тестируется веб-приложение SauceDemo

### Функциональные области

1. Авторизация
2. Каталог товаров
3. Сортировка товаров
4. Корзина
5. Оформление заказа
6. Навигация по приложению

## 4. Область тестирования (Scope)

### In Scope — входит в тестирование

* Вход с корректными учётными данными
* Проверка доступности каталога после входа
* Отображение товаров, названий и цен
* Сортировка товаров по названию и цене
* Добавление товаров в корзину
* Удаление товаров из корзины
* Проверка количества товаров в корзине
* Проверка обязательных полей формы оформления заказа
* Проверка переходов между этапами оформления заказа
* Проверка навигации между страницами

### Out of Scope — не входит в тестирование

* Нагрузочное и стресс-тестирование
* Тестирование безопасности на проникновение
* Проверка реальных платежей
* Тестирование серверной инфраструктуры
* Проверка базы данных приложения напрямую
* Кроссбраузерное тестирование, если не будет отдельно согласовано

## 5. Подход к тестированию

На первом этапе применяется исследовательское тестирование (Exploratory Testing)

На следующем этапе планируется:

* Подготовить чек-лист
* Разработать тест-кейсы
* Выполнить проверки по документированным сценариям
* Зафиксировать фактические и ожидаемые результаты
* Оформить подтверждённые дефекты
* Подготовить итоговый отчёт

Основные виды проверок:

* Функциональное тестирование
* Позитивное тестирование
* Негативное тестирование
* Проверка граничных условий
* Проверка переходов между состояниями приложения

* **Environment:** Web application

## 7. Критерии начала тестирования (Entry Criteria)

* Приложение доступно
* Подготовлена тестовая среда
* Определены функциональные области
* Доступны необходимые тестовые данные
* Определены основные пользовательские сценарии

## 8. Критерии завершения тестирования (Exit Criteria)

* Все запланированные тест-кейсы выполнены либо имеют зафиксированную причину невыполнения
* Результаты проверок задокументированы
* Все обнаруженные дефекты оформлены в виде баг-репортов
* Для критичных сценариев отсутствуют незадокументированные блокирующие проблемы
* Подготовлен итоговый тестовый отчёт

## 9. Риски

* Изменение поведения демонстрационного приложения
* Недоступность приложения во время тестирования
* Ограниченность тестовых данных
* Невозможность проверить серверную логику и базу данных напрямую
* Пропуск дефектов при исследовательском тестировании без заранее подготовленных сценариев

## 10. Предварительные результаты

В ходе первоначального исследовательского тестирования проверены следующие области:

* Авторизация — работает ожидаемо в рамках выполненных проверок
* Каталог — работает ожидаемо в рамках выполненных проверок
* Сортировка — работает ожидаемо в рамках выполненных проверок
* Корзина — работает ожидаемо в рамках выполненных проверок
* Оформление заказа — работает ожидаемо в рамках выполненных проверок
* Навигация — работает ожидаемо в рамках выполненных проверок

Подтверждённые дефекты на данном этапе не зарегистрированы

Результаты являются предварительными и не заменяют выполнение формализованных тест-кейсов
